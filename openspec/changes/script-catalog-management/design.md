## Context

目前，话术管理模块将所有话术存储在一个扁平的列表中，通过 `tags` 进行简单的过滤。随着话术数量增长，用户反馈列表混乱、查找困难。

我们需要引入层级结构（目录）来改善数据的组织形式。此外，用户界面目前强制显示不必要的标题字段，且操作路径较长。本次重构将引入**单层目录结构**，并改造前端 UI 以支持目录视图和时间轴视图的切换。

## Goals / Non-Goals

**Goals:**

1.  实现“目录”实体，支持 CRUD 操作。
2.  实现话术与目录的关联（1:N），支持话术移动、独立于目录存在（未分类）。
3.  前端实现“时间轴”与“目录”两种视图的无缝切换。
4.  优化话术卡片展示（去标题）及操作交互（便捷复制/删除确认）。
5.  提供灵活的目录删除策略（级联删除 vs 仅删除目录）。

**Non-Goals:**

1.  **多级目录**：本次仅支持单层目录，暂不考虑无限嵌套。
2.  **拖拽排序**：暂不支持话术或目录的自定义拖拽排序，默认按创建时间倒序。
3.  **批量操作**：暂不支持批量移动或删除话术 (除删除目录时的级联操作外)。

## Decisions

### 1. 数据模型设计

我们选择**单层目录**模型。

- **Rationale**: 保持系统简单轻量，满足绝大多数用户需求。多级目录会显著增加前端路由、面包屑导航以及后端查询的复杂度。
- **Schema**:
  - `Category`: `id`, `name`, `created_at`
  - `Script`: 增加 `category_id` (可空外键)。
- **Alternatives Considered**:
  - _多级目录 (Adjacency List / Nested Sets)_: 过于复杂，且对于移动端/小窗口应用来说，深层级导航体验不佳。
  - _仅使用 Tags_: 现有的 Tags 机制太灵活，缺乏“归档/文件夹”的强分类心智模型。

### 2. 目录删除策略

采用**用户决策**模式。

- **Rationale**: 删除目录是一个高风险操作。直接删除该目录下所有话术可能会导致严重的数据丢失。自动移动到根目录可能会导致根目录瞬间爆炸。因此，把选择权交给用户最安全。
- **Implementation**: API `DeleteCategory` 接受 `cascade` 参数。

### 3. 数据加载策略 (Frontend)

采用**全量加载 + 前端分组**。

- **Rationale**: 考虑到个人话术库规模通常在几百至几千条，全量加载的性能损耗（KB 级别数据）远小于频繁切换目录导致的网络/IPC 延迟。前端获取所有话术后，利用 Vue 的 `computed` 计算属性进行 `groupBy`，可以实现瞬时的视图切换体验。
- **Risk**: 当数据量达到 10k+ 时可能会有性能瓶颈。
- **Mitigation**: 未来可升级为按目录懒加载（`ListScripts(category_id)`）。目前维持全量加载。

## Risks / Trade-offs

- **[Risk] 数据迁移**: 旧版本用户没有 `category_id` 字段。
  - **Mitigation**: GORM AutoMigrate 会自动处理新增字段，旧数据默认为 `NULL`（即未分类），平滑过渡。
- **[Risk] 搜索体验**: 在目录视图下搜索，是搜当前目录还是全局？
  - **Decision**: 搜索应当是全局的。当用户开始搜索时，自动切换/展示为含有搜索结果的列表（不仅限于当前目录），或者高亮含有结果的目录。为了简化，初版搜索将暂时维持全局列表展示，搜索结束恢复视图。
